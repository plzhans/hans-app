# @krdata/mois

행정안전부(MOIS) 행정표준코드 API 클라이언트. 공공데이터포털(data.go.kr) 게이트웨이 `1741000`.

| 서비스       | 경로          | 오퍼레이션          |
| ------------ | ------------- | ------------------- |
| 행정표준코드 | `StanReginCd` | 법정동코드 조회 1개 |

원본 활용가이드(docx)는 [`openapi/1741000/origin/`](openapi/1741000/origin/) 에 보관한다.

## 같은 data.go.kr 인데 봉투가 다르다

**이 패키지가 따로 있는 이유다.** 게이트웨이는 공유하지만 그 뒤 서비스는 부처가 따로 만든 것이라
심평원·중앙의료원과 세 가지가 다르다. 그래서 `@krdata/core` 에 봉투 어댑터(`KrDataEnvelope`)를
두고 여기서 `MOIS_ENVELOPE` 를 주입한다. 재시도·한도·키 마스킹은 게이트웨이 몫이라 그대로 공유한다.

|               | 표준 (`@krdata/hira`·`nmc`) | 행정안전부 (`@krdata/mois`)        |
| ------------- | --------------------------- | ---------------------------------- |
| 포맷 파라미터 | `_type=json`                | **`type=json`**                    |
| 성공 코드     | `resultCode == '00'`        | **`INFO-0`**                       |
| 헤더 위치     | `response.header`           | **`<서비스명>[0].head[*].RESULT`** |
| 목록 위치     | `response.body.items.item`  | **`<서비스명>[1].row`**            |

## 가이드와 실제 API 가 다른 지점

전부 2026-08-04 실측으로 확인했다. 스펙(`openapi/1741000/StanReginCd.json`)의 해당 필드
설명에도 적어두었다.

- **`_type=json` 을 주면 봉투가 다른 응답이 온다.** 이름만 틀린 게 아니다.

  ```
  type=json  → {"StanReginCd":[{"head":[…]},{"row":[…]}]}   row 가 항상 배열
  _type=json → {"head":{…},"row":{…}}                       row 가 1건이면 단일 객체
  ```

  둘 다 주면 `type` 이 이긴다. `_type` 쪽은 게이트웨이가 XML 을 변환한 것이라 `type` 필드에
  `"XML"` 이 박혀 온다. 문서상 정식 경로인 `type=json` 을 쓴다.

- **가이드가 필수(1)로 표기한 `flag` 는 있으나 없으나 응답이 같다.** 스펙에 넣지 않았다.
- **결과가 없으면 봉투가 통째로 사라진다.** `{"RESULT":{"resultCode":"INFO-3","resultMsg":"데이터없음 에러"}}`
  만 온다. 가이드 에러표는 이 상황을 `200 INFO` 로 적었지만 실제 코드는 `INFO-3` 다.
  **페이지 범위를 넘겨도 같은 응답이라 에러로 다루지 않는다** — 던지면 페이지네이션 루프가
  마지막 페이지에서 터진다. `MOIS_ENVELOPE` 가 빈 결과로 통과시킨다.
- **`numOfRows` 상한은 1,000 이다.** 넘기면 가이드의 `336` 이 아니라 `{"resultCode":"ERROR-1"}` 이 온다.
- **잘못된 키가 XML 이 아니라 JSON 으로 온다.** `{"OpenAPI_ServiceResponse":{"cmmMsgHeader":{…}}}`
  형태다. `@krdata/core` 는 본문이 `<` 로 시작할 때만 에러로 봤기 때문에 **인증 실패가 정상 응답으로
  통과했다.** 이 JSON 형태를 감지하도록 core 에 추가했다 — 게이트웨이 공통이라 모든 패키지가 덕을 본다.
- **정렬 기준을 알 수 없지만 순서는 안정적이다.** 코드순도 이름순도 아니다(1페이지 첫 행이 대구다).
  같은 페이지를 반복 호출하면 항상 같은 순서라 페이지네이션은 안전하다.
- `locat_order` 는 가이드 표기와 달리 **숫자**로 온다. `adpt_de`(생성일)는 **빈 문자열인 행이 많다.**
- `locatadd_nm` 필터는 **부분일치**다. `송파` 로 14건이 걸린다.

## 운영 제약 — 배치 설계에 직결된다

- **초당 최대 30 TPS.** 병렬 호출은 호출부에서 제어하라.
- **개발계정 일 10,000건.** 운영계정은 활용사례 등록 시 증량 신청이 가능하다.
- **데이터 갱신주기 수시.** 일 1회 배치로 충분하다.

### 한 번에 1,000건씩 받는다 — 전량이 21콜이다

전체 20,560건이고 상한이 1,000 이라 **전량 수집이 21콜**이면 끝난다. 개발계정 한도(10,000)의
0.2% 다. 그래서 증분 수집을 만들지 않는다 — 원본에 변경분만 주는 파라미터가 없기도 하다.

`streamRegionCodes()` 의 기본 건수가 상한(1,000)인 이유다. 배열로 모으지 않고 페이지째
넘기므로 호출부가 받는 대로 적재하고 버릴 수 있다.

```ts
const client = new MoisClient({ serviceKey });

for await (const page of client.streamRegionCodes()) {
  await repository.upsert(page.rows); // 21번 돈다
}
```

## 코드 생성

```bash
pnpm --filter @krdata/mois codegen
pnpm krdata:codegen                   # data.go.kr 전체
```

생성물(`src/generated/`)은 커밋한다. 손으로 고치지 않는다.
