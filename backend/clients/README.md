# clients

외부 API 클라이언트(SDK). hansapi 도메인에 의존하지 않으며 단독으로 떼어낼 수 있어야 한다.
도메인 코드는 `packages/` 에 둔다.

| 패키지              | 설명                                                   |
| ------------------- | ------------------------------------------------------ |
| `@krdata/core`      | 공공데이터포털(data.go.kr) 공통 HTTP 처리              |
| `@krdata/nmc`       | 국립중앙의료원(NMC) 전국 병·의원 찾기 — 오퍼레이션 7개 |
| `@krdata/hira`      | 건강보험심사평가원(HIRA) 병원정보 — 오퍼레이션 18개    |
| `@seouldata/subway` | 서울열린데이터광장 지하철역 정보 — 오퍼레이션 1개      |

**포털이 다르면 패키지 계열이 다르다.** `@krdata/*` 는 공공데이터포털(data.go.kr),
`@seouldata/*` 는 서울열린데이터광장(openapi.seoul.go.kr)이다. 봉투가 근본적으로 달라서
`@krdata/core` 를 재사용할 수 없다 — 자세한 차이는 아래 표.

## 코드 생성 (orval)

각 기관 패키지는 `openapi/*.json` 을 **직접 작성**하고, orval 로 클라이언트를 생성한다.
API 스펙이 바뀌면 openapi 문서만 고치고 다시 생성한다.

```bash
pnpm krdata:codegen              # data.go.kr 전체
pnpm seouldata:codegen           # 서울열린데이터광장 전체
pnpm --filter @krdata/nmc codegen
pnpm --filter @seouldata/subway codegen
```

생성물(`src/generated/`)은 커밋한다. 손으로 고치지 않는다.

## data.go.kr 특이사항

생성된 코드로는 감당이 안 되는 부분이 있어 `@krdata/core` 의 mutator 가 흡수한다.
새 기관 클라이언트를 추가할 때도 이 규칙을 그대로 따른다.

- **`ServiceKey` 를 openapi 스펙에 넣지 말 것.** 발급키는 이미 퍼센트 인코딩된 문자열이라
  생성된 코드가 `URLSearchParams` 로 재인코딩하면 `%2B` → `%252B` 가 되어 401 이 난다.
  mutator 가 인코딩 없이 직접 붙인다.
- **`_type=json` 도 스펙에 넣지 말 것.** 이 값을 주지 않으면 XML 로 응답한다. mutator 가 항상 주입한다.
- **에러가 XML 로 올 수 있다.** `_type=json` 을 줘도 서비스키 오류 등은 XML 로 떨어진다.
  mutator 가 본문이 `<` 로 시작하면 에러로 판정한다.
- **응답이 스펙대로 오지 않는다.** 결과 0건이면 `items` 가 빈 문자열(`""`)로 오고,
  1건이면 `items.item` 이 배열이 아니라 단일 객체로 온다. 숫자 필드가 문자열로 오기도 한다.
  앞의 두 가지는 `normalizeKrDataResponse` 가 항상 배열이 되도록 보정한다.
  타입 불일치는 런타임 검증을 하지 않으므로 그대로 통과시킨다 — 어차피 JSON 원본을 통째로 적재한다.

## NMC 운영 제약

공식 가이드(NIA OpenAPI 활용 가이드, SC-IFT-01-02) 기준.

- **초당 최대 30 TPS.** 병렬 호출은 호출부에서 제어하라.
- **데이터 갱신주기 일 1회.** 배치도 하루 한 번이면 충분하다.
- 가이드상 최대 메시지 사이즈는 4000 bytes 지만 **실제로는 지켜지지 않는다.**
  `numOfRows` 를 크게 주면 수십 MB 응답도 그대로 내려온다.

## 가이드와 실제 API 가 다른 지점

전부 2026-07 실측으로 확인했다. 스펙(`openapi/nmc.json`)의 해당 필드 설명에도 적어두었다.

- `/CodeMast/info` 의 대분류코드 필터는 **요청 파라미터명이 대문자 `CM_MID`** 다.
  응답 필드명(`cmMid`)과 표기가 달라 헷갈린다. 소문자로 보내면 **서버가 조용히 무시하고**
  에러 없이 전체 코드를 반환하므로, 필터가 안 먹는 걸 API 버그로 오인하기 쉽다.
  (`CM_MID=H010` → 14건 / `cmMid=H010` → 전체 2,784건)
- 기본정보 조회의 **`hv*` 7개 필드(hvec, hvoc, hvcc, hvncc, hvccc, hvicc, hvgc)가 응답에 오지 않는다.**
  응급실 운영 기관도 마찬가지다. 실시간 가용병상이 필요하면 별도 API 를 써야 한다.
- **`dutyLvkl`(운영상태)은 위치정보 응답에만 온다.** 가이드의 목록·FullDown XML 예제에는 있지만
  현재 API 는 주지 않는다.
- 숫자 필드가 문자열로 오거나 그 반대인 경우가 섞여 있다. (`dutyTime1c`=2000, `dutyTime6s`="0930")
  런타임 검증을 하지 않으므로 그대로 통과시킨다.

## HIRA

서비스 3개를 한 스펙에 묶었다. 모두 기관코드 `B551182` 아래에 있다.

| 서비스                   | 경로                    | 오퍼레이션             |
| ------------------------ | ----------------------- | ---------------------- |
| 병원정보서비스           | `hospInfoServicev2`     | 병원 기본목록 1개      |
| 병원코드정보서비스       | `codeInfoService`       | 코드 6종               |
| 의료기관별상세정보서비스 | `MadmDtlInfoService2.7` | `ykiho` 기준 상세 11종 |

### 공식 가이드의 엔드포인트가 낡았다

가이드(2021) 경로로 호출하면 `Unexpected errors` 가 난다. 현행 경로는 아래다. (2026-07 실호출 확인)

| 가이드                               | 실제                                   |
| ------------------------------------ | -------------------------------------- |
| `hospInfoService1/getHospBasisList1` | `hospInfoServicev2/getHospBasisList`   |
| `MadmDtlInfoService2/getDtlInfo2`    | `MadmDtlInfoService2.7/getDtlInfo2.7`  |
| —                                    | `codeInfoService/*` (버전 접미사 없음) |

### 운영 제약 — 배치 설계에 직결된다

- **초당 최대 30 TPS**
- **개발계정 일 1,000건 트래픽.** 병원이 **79,739개**라 `ykiho` 단위 상세 조회는
  오퍼레이션 하나당 80일이 걸린다. 상세 11종을 다 모으려면 산술적으로 877,000콜이다.
  **운영계정 전환 없이는 상세정보 전량 캐싱이 불가능하다.**

### 가이드와 실제 API 가 다른 지점

- `getEqpInfo2.7` 은 이름이 장비(Equipment)지만 실제 내용은 **시설·병상 정보**다.
  의료장비는 `getMedOftInfo2.7` 이다. 그래서 파사드 이름을 `getFacilityInfo` /
  `getEquipmentInfo` 로 바로잡았다.
- 병원 목록의 **`pnursCnt` 는 가이드에 없는 필드**다. 값이 대부분 0 이고 드물게 한 자릿수라
  전문간호사 수로 추정된다.
- 시설정보의 **`dtrmSbdCnt` 는 가이드 응답 표에 없다.** 낮병동 병상수로 추정된다.
- 좌표 필드가 **응답은 대문자 `XPos`/`YPos`, 요청은 소문자 `xPos`/`yPos`** 다.
- **HIRA 와 NMC 는 코드 체계가 완전히 다르다.** 진료과목이 HIRA 는 `01`(내과), NMC 는
  `D001`(내과) 이고, 종별도 HIRA 는 `01`/`11`/`31`, NMC 는 `A`/`B`/`C` 다. 섞어 쓰면 안 된다.

## 서울열린데이터광장 (`@seouldata/*`)

> **`@seouldata/subway` 는 지금 아무도 쓰지 않는다. 껍데기로 남겨 둔 것이다.**
>
> 지하철역 다국어 사전은 **`backend/data/전국 도시광역철도 역사 역사정보_*.xlsx`** 로 만든다.
> 국가철도공단 표준데이터이고 **전국**(부산·대구·대전·광주 포함) 1,108역에 영문 결측이 0 이다.
> 서울 API 는 **수도권 전철 799행뿐**이라 그 상위집합이 못 된다. 병원 하차역 578개 기준으로
> 엑셀이 못 채우는 걸 서울 API 가 채워주는 건 3역에 불과하다(구로·청계산입구·인하대).
> 그 3역 때문에 소스를 둘로 유지하면 표기 체계가 갈라진다 — 엑셀 하나로 간다.
>
> 남겨 둔 이유는 서울열린데이터광장의 **다른** 데이터셋(따릉이·인구 등)을 붙일 때 이 봉투 처리를
> 그대로 재활용하기 위해서다. 그때 `http.ts`/`error.ts` 를 `@seouldata/core` 로 올리면 된다.

data.go.kr 과 봉투가 다르다. `@krdata/core` 를 못 쓰는 이유이자, 새 서울 데이터셋을 붙일 때
그대로 따라야 할 규칙이다.

|           | data.go.kr (`@krdata/*`)  | 서울열린데이터광장 (`@seouldata/*`) |
| --------- | ------------------------- | ----------------------------------- |
| 인증키    | 쿼리 `ServiceKey=`        | **경로 첫 세그먼트** `/{KEY}/...`   |
| 파라미터  | 쿼리                      | **위치 기반 경로 세그먼트**         |
| 응답 포맷 | 쿼리 `_type=json`         | 경로 `/json/`                       |
| 성공 판정 | `header.resultCode == 00` | `RESULT.CODE == 'INFO-000'`         |
| 응답 봉투 | `response.body.items`     | `{ "<서비스명>": { row: [...] } }`  |

- **인증키를 openapi 스펙에 넣지 말 것.** mutator(`http.ts`)가 `baseUrl` 뒤에 경로로 붙인다.
- **에러 메시지에 URL 을 남기지 말 것.** 키가 경로에 있어서 URL 이 곧 키 유출이다.
  `toServiceName()` 으로 서비스명만 뽑아 쓴다.
- **위치 기반 파라미터는 건너뛸 수 없다.** 필터하지 않을 자리에는 공백 한 칸(`' '`)을 넣는다.
  빈 문자열을 넣으면 세그먼트가 사라져 **뒤 파라미터가 한 칸씩 밀린다.**
- **에러가 JSON 요청에도 XML 로 온다.** `ERROR-335` 는 XML, `ERROR-500` 은 JSON 이었다.
  (2026-07 실측) `http.ts` 가 본문이 `<` 로 시작하면 XML 로 판정한다.
- **`INFO-200`(데이터 없음)은 에러가 아니다.** 빈 결과로 통과시킨다.
- 인증키 없이 `'sample'` 로 스키마를 확인할 수 있다. 단 **한 번에 5건까지**(ERROR-335).

### 지하철역 정보 — 실측 기록 (2026-07, 정식 키로 전량 확인)

**이 데이터를 사전으로 쓰지 않기로 한 근거다.** 다시 끌어다 쓰려 할 때 같은 조사를 반복하지
않도록 남긴다.

전량 799행 / 고유 역명 654개 / 24개 노선. **수도권 전철만이다.**

- **환승역은 노선마다 행이 따로 나온다.** `STATION_CD` 도 노선마다 다르다 — 역 식별자로 쓰지 마라.
- **같은 역의 표기가 노선마다 다르다.** 일문 14건, 영문 5건 충돌.
  `서울역` → `ソウル`(1호선) vs `ソウルヨク`(4호선), `김포공항` → `キンポ` / `キンポゴンハン` / `キンポ空港`
- **일문 칸에 중국어 한자가 섞여 있다.** 고유 23역이 어느 노선에서도 가나를 못 얻는다
  (일산선 삼송·원당·화정·백석·마두·정발산·주엽·대화, 인천2호선 대부분).
- **틀린 값도 있다.** 신분당선 `신논현` 의 일문이 `カンナム`(강남)이다.
- 엑셀과 교차 대조하면 **양쪽 다 가나로 준 619역 중 84역(14%)이 값이 다르다.** 어느 쪽이 맞는지는
  케이스마다 갈린다 — `귤현` 은 엑셀이 맞고, `망우` 는 서울 API 가 맞다.
- 영문에 이중 공백(`Dongdaemun History  Culture Park`), 중문에 괄호 병기(`...(DDP)`)가 있다.
- `listAllStations()` 는 정식 키로 799행을 한 번에 가져온다(1콜). 페이지네이션만 대신 돌려주고
  값은 손대지 않는다.
