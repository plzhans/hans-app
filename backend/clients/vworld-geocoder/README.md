# @vworld/geocoder

국토교통부 공간정보 오픈플랫폼(브이월드) 지오코딩 API 클라이언트. `api.vworld.kr`

| 오퍼레이션   | 방향        | 스펙                            |
| ------------ | ----------- | ------------------------------- |
| `GetCoord`   | 주소 → 좌표 | `openapi/geocoder-coord.json`   |
| `GetAddress` | 좌표 → 주소 | `openapi/geocoder-address.json` |

> **지금 아무도 쓰지 않는다. 껍데기로 남겨 둔 것이다.**
>
> 원래 용도는 **사용자 위경도로 시도를 뽑는 것**(역지오코딩)이었는데, 그 문제는 병원 데이터에서
> 시도를 뽑는 방식으로 이미 해결됐다. 병원 좌표도 원본이 이미 준다 —
> HIRA 는 `XPos`/`YPos`, NMC 는 `wgs84Lon`/`wgs84Lat` 이다.
>
> 그래도 남겨 둔 이유는 **주소를 좌표로 바꿔야 하는 자리가 다시 생길 수 있어서**다.
> 원본 좌표가 비었거나 틀린 병원을 보정하는 경우가 대표적이다.
> 붙일 때는 아래 **이용약관** 항목을 먼저 확인하라.

## 이용약관 — 적재 전에 확인이 필요하다

가이드에 이렇게 적혀 있다.

> API 요청은 실시간으로 사용하셔야 하며 **별도의 저장장치나 데이터베이스에 저장할 수 없음**

호출은 문제없지만 **결과를 DB 에 쌓는 용도**는 이 문구에 걸린다. `@kr-or/hira` 와 같은 상태라
배치·적재 경로에 넣지 않았다. 실시간 조회로만 쓰면 해당되지 않는다.

## 왜 별도 계열인가

**포털이 다르면 패키지 계열이 다르다**는 규칙 그대로다. 기관(국토교통부)이 아니라 포털이 기준이다.
심평원이 `@krdata/hira`(data.go.kr)와 `@kr-or/hira`(자체 홈페이지)로 갈린 것과 같은 이유다.

|            | data.go.kr (`@krdata/*`)  | 브이월드 (`@vworld/*`)         |
| ---------- | ------------------------- | ------------------------------ |
| 인증키     | `ServiceKey=`             | **`key=`**                     |
| 성공 판정  | `header.resultCode == 00` | **`response.status == 'OK'`**  |
| 에러       | XML 또는 JSON 봉투        | **HTTP 200 + `status: ERROR`** |
| 오퍼레이션 | 경로로 구분               | **`request` 쿼리로 구분**      |

`@krdata/core` 를 재사용할 수 없어 자체 `http.ts`/`error.ts` 를 둔다. (`@kr-go/nts` 와 같은 구조)

## 스펙 파일이 둘인 이유

두 오퍼레이션이 **같은 경로·같은 메서드**(`GET /req/address`)를 쓰고 `request` 파라미터로만
갈린다. OpenAPI 는 같은 path+method 를 두 번 정의할 수 없어 오퍼레이션마다 스펙을 나눴다.
`request` 값은 mutator 가 주입한다 — 호출부가 어느 오퍼레이션인지 알려준다.

## 가이드와 실제 API 가 다른 지점

전부 2026-08-04 실측으로 확인했다. 스펙의 해당 필드 설명에도 적어두었다.

- **가이드에 없는 `response` 래퍼가 한 겹 더 있다.**

  ```
  가이드   { "service": …, "status": "OK", "result": … }
  실제     { "response": { "service": …, "status": "OK", "result": … } }
  ```

  가이드대로 파싱하면 전부 어긋난다. 클라이언트가 이 래퍼를 벗겨서 내보낸다.

- **좌표가 숫자가 아니라 문자열로 온다.** `"127.05074925950022"` — 클라이언트가 숫자로 바꾼다.
- **에러가 HTTP 200 으로 온다.** 상태코드로는 실패를 알 수 없어 본문 `status` 를 봐야 한다.
- **`NOT_FOUND` 면 `result` 가 없고 대신 `record`·`page` 가 온다.** 가이드에 없는 필드다.
  역지오코딩은 `input` 만 오고 그때 `input.crs` 가 빈 문자열이다.
- **`level3` 을 일반구로 믿으면 안 된다.** 가이드는 '(일반구)구'라는데 일반구가 없는 서울 동대문구
  조회에 `'회기동'`이 왔다. 같은 좌표에서도 지번 항목은 빈 문자열, 도로명 항목은 `'회기동'`이었다.
- **`level4LC` 가 오퍼레이션마다 다르다.** `GetCoord` 에서는 비어 있는데,
  `GetAddress` 의 지번 항목에서는 **법정동코드**(`1123010800`)가 채워진다.
- **역지오코딩의 `type` 이 가이드상 선택인데 실제로는 필수다.** 빼면 `PARAM_REQUIRED` 로 거절된다.
  기본값 `BOTH` 가 적용되지 않는다.
- 역지오코딩 항목의 `type` 이 **소문자**다(`'parcel'`·`'road'`). 요청 파라미터는 대문자를 쓴다.
- `service.time` 이 숫자가 아니라 `'16(ms)'` 형태의 문자열이다.

### 행정동코드와 법정동코드는 다른 체계다

`level4AC` 는 **행정동코드** 10자리다(`1123071000`). `mois_region_code` 의 법정동코드와
자릿수가 같아서 헷갈리기 쉬운데 **서로 다른 체계이므로 섞어 쓰면 안 된다.**
법정동코드가 필요하면 `GetAddress` 의 지번 항목에서 `level4LC` 를 본다.

## 운영 제약

- **일일 요청 한도 40,000건.** 초과하면 `OVER_REQUEST_LIMIT` 이고 `VworldQuotaError` 로 던진다.
- **인증키는 공공데이터포털과 별개다.** vworld.kr 에서 따로 발급받는다.
- **도메인 제한을 받지 않는다.** Referer·Origin 을 바꿔 호출해도 통과한다(2026-08 실측).
  즉 서버에서 부를 수 있다. 지도 API(WMS·3D)는 도메인을 검사하지만 REST 지오코딩은 아니다.
- **키가 쿼리스트링에 실린다.** 브라우저에서 부르면 그대로 노출되고 일 한도를 남이 갉아먹는다.
  서버에서 부르고 결과만 내려주는 편이 안전하다. 에러 메시지에 URL 을 남기지 않는 이유이기도 하다.

## 사용

```ts
const client = new VworldGeocoderClient({ serviceKey });

// 주소 → 좌표. 못 찾으면 null (예외가 아니다)
const c = await client.geocode({
  address: '서울특별시 동대문구 경희대로 23',
  type: 'ROAD',
});
// { lon: 127.0507…, lat: 37.5937…, crs: 'EPSG:4326', refined: { text, structure } }

// 좌표 → 주소. point 는 '경도,위도' 순이다
const items = await client.reverseGeocode({
  point: VworldGeocoderClient.toPoint(127.0507, 37.5937),
  type: 'BOTH', // 가이드와 달리 필수다
});
// [{ type: 'parcel', zipcode, text, structure }, { type: 'road', … }]
```

`type` 에 기본값을 두지 않았다. 주소 형태와 어긋나면 조용히 `NOT_FOUND` 가 되기 때문에
호출부가 어떤 주소인지 알고 넘겨야 한다.
