# @kr-or/hira

건강보험심사평가원 **홈페이지**(www.hira.or.kr)의 비급여 진료비 클라이언트.

**@krdata/hira 와 다른 패키지다.** 기관은 같은 심평원이지만 포털이 다르면 계열이 다르다는
규칙(`clients/README.md`)을 그대로 따른다. `@krdata/*` 는 공공데이터포털(data.go.kr)의 공개
API 고, 이 패키지는 심평원 자체 홈페이지의 내부 ajax 엔드포인트다.

|               | `@krdata/hira`      | `@kr-or/hira` (이 패키지)                        |
| ------------- | ------------------- | ------------------------------------------------ |
| 정체          | 활용신청한 공개 API | 홈페이지 내부 ajax                               |
| 인증          | ServiceKey          | **없음**                                         |
| 코드 생성     | orval               | **손으로 작성** (openapi 스펙이 존재하지 않는다) |
| 안정성        | 스펙 있음           | **예고 없이 바뀔 수 있다**                       |
| 의원(clCd=31) | **없다**            | **있다**                                         |

## 존재 이유

data.go.kr 의 비급여진료비정보조회서비스에는 **의원급이 통째로 없다.** 병원 79,739개 중
대부분이 의원이므로 이건 작은 구멍이 아니다. 2026-07 에 확인한 내용:

- `nonPaymentDamtInfoService` 에 실재하는 오퍼레이션은 5개뿐이고 전부 포털 문서에 있는 것들이다.
  숨은 의원급 오퍼레이션은 **없다**(`API not found` / `Unexpected errors` 응답으로 30여 개 후보를
  전수 확인했다).
- 레거시 `getNonPaymentItemHospList`(16.2월 이전) 도 `clCd=31` 필터 결과가 0건이다.
- 반면 이 홈페이지 엔드포인트는 의원급을 그대로 준다. 예: 아빠미소소아청소년과의원 23건.

병원급 이상은 `@krdata/hira` 를 쓴다. **이 패키지는 의원급을 메우는 용도다.**

## 사용

```ts
import { HiraNpayClient } from '@kr-or/hira';

const client = new HiraNpayClient(); // 설정 없이 동작한다 — 키가 없다

// ykiho 는 @krdata/hira 의 기관 목록에서 받은 그 암호화 문자열이다.
const { hospitalId, items, published } =
  await client.listNonPaymentItems(ykiho);
```

`items` 가 비었다고 실패가 아니다. 공개할 비급여가 없는 기관이 실제로 많고, 그 구분은
`published`(응답의 `npayPubListGbn`)로 한다.

## 호출 흐름

```
1. GET  /ra/hosp/hospInfoAjax.do?ykiho=<암호화 ykiho>
     → HTML 안의 <input id="ykiho" value="41356837"> 에서 숫자 기관 ID 추출
2. POST /ra/eval/diagAmtInfoAjax.do   (form: ykiho=41356837)
     → JSON
```

2번은 숫자 ID 만 있으면 되므로 **매핑을 저장해 두면 1번을 영구히 건너뛴다**(요청 수 절반).
`resolveHospitalId` 와 `fetchItems` 가 나뉘어 있는 이유다.

숫자 ID 는 `41356837`·`13318977`·`11332468` 처럼 연속값으로 보이지만 **순회하지 마라.**
유효 ID 를 찾아 훑는 순간 성격이 '공개 정보 조회'에서 'ID 열거'로 바뀐다. 매핑은 반드시
`@krdata/hira` 에서 받은 기관 목록의 ykiho 로만 채운다.

## 실측 (2026-07)

- **인증·세션·토큰이 전혀 없다.** Referer·Origin·User-Agent·쿠키 어느 것도 검사하지 않고,
  POST 대신 GET 으로도 응답이 같다. `curl "…/diagAmtInfoAjax.do?ykiho=41356837"` 한 줄이면 된다.
- **그럼에도 Referer 를 항상 붙인다.** 브라우저가 실제로 밟는 경로(같은 기관의 암호화 ykiho 가
  들어간 상세 페이지 URL)를 그대로 흉내낸다. 검사하지 않는다는 이유로 빼는 '최적화'를 하지 마라.
  그래서 `fetchItems(hospitalId, encryptedYkiho)` 의 두 번째 인자가 옵션이 아니라 필수다.
- 응답의 `data.npayMdivList` 는 `data.npayPubList` 를 중분류로 묶은 중복이고, `data.template` 은
  렌더링된 HTML 통짜다. 둘 다 버리고 `npayPubList` 만 쓴다.
- `minPrc`/`maxPrc` 는 그 기관 값이지만 `middPrc`/`hifrqPrc`/`wgtAvgCprc` 는 전체 기관 통계로
  보인다. **미검증이다** — 그 기관 값으로 쓰지 마라.

## 속도

`minIntervalMs` 기본값이 1000 이고 **0 으로 낮추지 마라.** 인증도 쿼터도 없어서 서버가 우리를
막아 주지 않는다 — 속도 조절 책임이 전적으로 이쪽에 있다. 의원만 7만 곳이라 전량이면 이 간격으로도
20시간이 넘는다(매핑을 캐시해 step1 을 건너뛴 기준). 공식 API 가 아니라 그만한 부하를 상정한
서버가 아니므로, 전량 순회보다 **필요한 지역·과목으로 좁히는 쪽**을 먼저 검토하라.

## 법무 확인 전이다

**아직 배치로 상시 적재하지 마라.** 심평원 홈페이지 이용약관(2026-07 확인):

- 제10조 ①2 — 서비스로 얻은 정보를 **개인적인 이용 외에** 복제·배포하거나 **제3자에게 제공** 금지
- 제10조 ⑨ — 얻은 정보를 가공·판매하는 등 **상업적으로 사용 금지**

이 둘이 hans-app 적재·노출에 정면으로 닿는다. 반면 걸리지 **않는** 것들도 분명히 해둔다:

- robots.txt 는 `/co/`(통합검색)만 막는다. `/ra/` 는 대상이 아니고 `Crawl-delay` 도 없다.
- 약관의 크롤러 조항(제10조 ①9)은 '**로그인 자동화**'와 '**개인정보 포함 서비스**(투약내역·진료내역)
  수집'으로 한정돼 있다. 이 엔드포인트는 로그인도 개인정보도 없는 기관별 공개 가격표라 해당 없다.
- 데이터 자체는 의료법 제45조의2 에 따라 **공개가 법으로 의무화된 정보**다. 공공데이터법상 제공
  대상으로 볼 여지가 있고, 그렇다면 홈페이지 약관보다 그쪽이 우선한다는 해석이 가능하다. 다만
  법률 판단이 필요한 영역이고, data.go.kr 에 병원급만 올라와 있다는 사실 자체가 심평원이 의원급을
  아직 개방 대상으로 안 봤다는 신호일 수도 있다.

정공법은 심평원에 **공공데이터 제공신청**을 넣거나 약관이 말하는 **사전승낙**을 받는 것이다.
그때까지 이 패키지는 조사·검증용으로만 쓴다.
