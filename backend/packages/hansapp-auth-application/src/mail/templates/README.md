# 메일 템플릿

발송 메일의 HTML 양식을 둔다. **이 폴더의 `.html` 이 소스다** — 브라우저로 직접 열어 렌더를
확인하고, Litmus / Email on Acid 에 붙여 클라이언트별 렌더를 본다.

[`MailService`](../mail.service.ts) 가 이 HTML 을 읽어 플레이스홀더를 치환한 뒤 SMTP 로 발송한다.

## 파일 목록

| 파일                     | 쓰는 메일                          | 왜 이렇게 묶였나                    |
| ------------------------ | ---------------------------------- | ----------------------------------- |
| `verification-code.html` | 가입 이메일 인증 · 비밀번호 재설정 | 마크업이 같다. 문구만 다르다        |
| `signup-welcome.html`    | 가입 축하                          | 경고 박스가 없고 정보 박스가 이메일 |
| `password-changed.html`  | 비밀번호 변경 · 설정 · 재설정      | 경고 박스가 있고 제공자 줄이 없다   |
| `social-changed.html`    | 소셜 연동 · 연동 해제              | 마크업이 같다. 문구만 다르다        |

## 나누는 기준

**텍스트 치환만으로 갈리면 한 파일, 구조가 갈리면 다른 파일.**

조건부 블록(`{{#if}}` 같은 것)은 두지 않는다. 넣는 순간 HTML 만 열어서는 이 파일이 무슨
메일인지 읽히지 않고, 어느 조합이 실제로 나가는지 코드까지 따라가야 알 수 있다.
**렌더러도 치환밖에 못 한다** — 분기가 필요해 보이면 그건 파일을 나눌 신호다.

그래서 이렇게 갈렸다.

- `verification-code` — 가입 인증과 재설정은 코드 박스·만료 안내·보안 문구 자리가 모두 같다.
  바뀌는 것은 제목과 문단뿐이라 **슬롯으로 충분하다.** 예전에는 파일이 둘이었고, 코드 박스를
  한쪽만 고치는 사고를 막으려고 주석에 "한쪽을 고치면 함께 고칠 것" 이라고 적어 두고 있었다 —
  같이 고쳐야 하는 것은 한 파일이어야 한다.
- `social-changed` — 연동과 해제도 같은 이유다. 마크업이 글자 하나까지 같다.
- 나머지 둘 — **구조가 다르다.** 가입 축하에는 호박색 경고 박스가 없고, 비밀번호 변경에는
  제공자 줄이 없다. 이건 슬롯으로 못 없앤다.

## 언어별 파일은 없다

**보이는 문구가 전부 플레이스홀더라 파일에 한국어가 없다.** 그래서 이름에 `.ko` 같은
locale 접미사를 붙이지 않는다 — 붙이면 "한국어 판" 이라는 거짓말이 된다.

문구는 `MailService` 의 표에서 골라 넣는다.

| 표             | 담는 것                                          |
| -------------- | ------------------------------------------------ |
| `CODE_I18N`    | 코드 메일 문구(용도별: 가입 / 재설정)            |
| `CODE_SHELL`   | 코드 메일 공통 조각(인사말 · 발신전용 고지 등)   |
| `NOTICE_I18N`  | 알림 문구(종류별: 축하 / 비밀번호 / 연동 / 해제) |
| `NOTICE_SHELL` | 알림 공통 조각(경칭 · 라벨 등)                   |

지원 언어는 **한국어와 영어**다. 언어를 늘리려면 파일이 아니라 이 표에 한 줄씩 더한다.
레이아웃 자체를 언어별로 달라져야 할 일이 생기면 그때 파일을 나눈다.

## 플레이스홀더 계약

값은 `MailService` 가 채운다. 사용자 입력에서 오는 값(`userNameGreeting`)은 **HTML 이스케이프된다.**

### 공통

| 플레이스홀더           | 의미                                      | 예시                             |
| ---------------------- | ----------------------------------------- | -------------------------------- |
| `{{lang}}`             | `<html lang>` 값                          | `ko`                             |
| `{{appName}}`          | 서비스 표시명(`APP_NAME`)                 | `HansApp`                        |
| `{{appUrl}}`           | 서비스 홈 URL(로고 링크)                  | `https://plzhans.com`            |
| `{{greeting}}`         | 인사말                                    | `안녕하세요`                     |
| `{{userNameGreeting}}` | 인사말 뒤 이름 조각. **없으면 빈 문자열** | ` 홍길동 님` / `` (앞 공백 포함) |
| `{{heading}}`          | 큰 제목                                   | `비밀번호 재설정 코드`           |
| `{{message}}`          | 본문 한 문단                              | `아래 인증 코드를 입력해 …`      |
| `{{footerLegal}}`      | 발신전용 고지                             | `이 메일은 발신 전용입니다.`     |
| `{{copyright}}`        | 푸터 저작권 한 줄                         | `© 2026 HansApp`                 |

### 코드 메일 (`verification-code`)

| 플레이스홀더       | 의미                                   | 예시                                 |
| ------------------ | -------------------------------------- | ------------------------------------ |
| `{{code}}`         | 인증 코드(OTP)                         | `846210`                             |
| `{{expiresNote}}`  | 유효기간 안내. **분이 이미 박혀 온다** | `이 코드는 10분 동안만 유효합니다.`  |
| `{{securityNote}}` | "본인이 요청하지 않았다면 …"           | `… 이 메일을 무시하세요.`            |
| `{{neverAskNote}}` | 코드를 묻지 않는다는 고지              | `HansApp 는 어떤 경우에도 …`         |
| `{{preheader}}`    | 받은편지함 미리보기 한 줄              | `HansApp 인증 코드는 846210 입니다.` |

### 알림 메일 (`signup-welcome`, `password-changed`, `social-changed`)

| 플레이스홀더                         | 의미                                   | 예시                                    |
| ------------------------------------ | -------------------------------------- | --------------------------------------- |
| `{{detailLabel}}`                    | 정보 박스 라벨                         | `처리 시각` / `가입한 이메일`           |
| `{{detail}}`                         | 정보 박스 값                           | `2026. 8. 7. 오후 2:30 (KST)`           |
| `{{providerLabel}}` / `{{provider}}` | 제공자 줄 (`social-changed` 만)        | `소셜 계정` / `Google`                  |
| `{{alertNote}}`                      | 호박색 경고 박스 문구 (가입 축하 제외) | `본인이 변경한 것이 아니라면 …`         |
| `{{closingNote}}`                    | 경고 박스 아래 회색 각주               | `본인이 한 일이 맞다면 …`               |
| `{{ctaUrl}}` / `{{ctaLabel}}`        | 버튼                                   | `https://plzhans.com` / `계정 확인하기` |

`{{detail}}` 은 보안 알림에서 **처리 시각**이다. 본인이 한 일인지 가리는 유일한 단서라
비울 수 있게 두지 않았다. 가입 축하에서만 가입 이메일로 바뀐다.

### 강조 태그가 든 문구

`message` · `expiresNote` · `securityNote` 는 `<strong>` 을 품는다. 이 셋은 **우리가 만든
문구라** `render` 의 세 번째 인자(raw)로 넘겨 이스케이프하지 않는다.
**사용자 입력을 절대 여기 넣지 말 것** — 이름 같은 값은 일반 vars 로 보내야 한다.

## 코드(OTP)와 만료

인증 코드는 [`EmailVerificationService`](../email-verification.service.ts) 가 발급·검증한다
(6자리·기본 10분 TTL·시도제한·1시간 발송 상한). 발송은 `issueAndSend` → `MailService` 가
템플릿을 렌더해 SMTP 로 보낸다. 코드·이메일은 원문 대신 HMAC 해시로만 DB(`email_verification`)에 남는다.

- 만료 분은 실제 코드 TTL(`MAIL_OTP_TTL_SEC`, 기본 600초)과 자동으로 맞춰진다.
- 코드는 숫자 6자리를 권장(입력·읽기 쉬움). 자릿수를 바꾸면 `.code-box` 의 `letter-spacing`/
  `font-size` 를 눈으로 확인할 것(모바일은 `.sm-code` 로 축소된다).

## 텍스트(plain) 대체본

`MailService` 가 문구 표에서 만든다. 별도 `.txt` 템플릿은 두지 않는다 — HTML 에서 강조
태그만 걷어내면 되는 수준이라 파일을 늘릴 값이 없다. 스팸 필터가 텍스트 파트 없는 메일을
불리하게 보므로 **빼지 말 것.**

## 빌드에서 누락되지 않게 하는 장치

`.html` 은 tsc 가 옮겨 주지 않는다. 그래서 **세 겹으로 막아 뒀다.**

**1. 패키지 build 가 복사한다**

```
tsc -p tsconfig.json && mkdir -p dist/mail/templates && cp src/mail/templates/*.html dist/mail/templates/
```

와일드카드라 파일을 새로 추가해도 스크립트를 고칠 필요는 없다. 폴더가 통째로 사라지면
`cp` 가 실패해 빌드가 멈춘다.

**2. `package.json` 의 `files` 가 dist 를 명시한다**

```json
"files": ["dist"]
```

`pnpm deploy` 는 이 목록대로 추려 이미지에 넣는다. 없어도 기본값이 dist 를 포함하긴 하지만,
그건 **우연히 되는 것**이라 명시한다(형제 패키지 `@hansapp/llm` · `@hansapp/search` 와 같은 규칙).
덤으로 `src/` 가 이미지에서 빠진다.

**3. 부팅 때 전부 읽어 본다**

`MailService.onModuleInit` 이 `ALL_TEMPLATES` 를 모두 로드하고, 하나라도 없으면 **예외를
던져 앱을 못 뜨게 한다.** 템플릿을 새로 만들면 그 목록에도 올려야 한다.

이 검사가 필요한 이유는 실패가 **로컬에서 안 보이기 때문**이다 — 로컬은 SMTP 미설정이라
발송을 건너뛰어 렌더까지 가지도 않는다. 조용히 배포되면 가입하려던 사람이 대신 실패한다.
컨테이너가 안 뜨면 배포가 실패하고 롤백되니, 앞쪽에서 터지는 편이 낫다.

```
Mail templates are missing from the build: social-changed.html
(looked in /app/.../dist/mail/templates).
Check the "cp src/mail/templates/*.html" step in @hansapp/auth-application build.
```
