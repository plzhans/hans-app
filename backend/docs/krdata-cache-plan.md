# 공공데이터 로컬 DB 캐싱 계획 (NMC / HIRA)

원본 API는 느리고 콜수 제한이 있어 매 요청마다 호출할 수 없다.
배치로 로컬 DB에 적재해두고 서비스는 DB만 조회한다.

이 문서는 **무엇을 어떤 순서로, 몇 콜에 받을지**를 정한다.

작성 기준: 2026-07. 건수·콜수는 모두 실호출로 측정한 값이다.
SDK는 `clients/krdata-nmc`, `clients/krdata-hira` 에 있고 API 특이사항은 `clients/README.md` 를 본다.

## NMC 와 HIRA 는 단계를 공유하지 않는다

두 기관은 API 구조가 달라 배치의 실행 단위 자체가 다르다. 단계 번호를 공유하면 맞지 않는다.

- **NMC**: 개별 조회 API 가 `basic` **하나뿐**이다. 한 콜에 68개 필드가 온다.
  배치는 **병원 등급으로만** 나뉜다. 사다리가 짧다.
- **HIRA**: 개별 조회가 **11종 오퍼레이션**으로 쪼개져 있다. 한 병원을 완성하려면 11번 두드려야 한다.
  배치의 실행 단위는 **병원 등급**이고, 한 등급을 잡으면 11종을 다 돌려 그 등급을 완성한다.
  사다리가 길고 콜수가 NMC 의 11배다.

그래서 아래 두 사다리를 **독립적으로** 진행한다. 서로를 기다리지 않고, 서로를 참조하지도 않는다.
두 기관의 데이터는 별개다. 한쪽 데이터로 다른 쪽을 대신하지 않는다.

## 전제

| 항목             | NMC                 | HIRA                           |
| ---------------- | ------------------- | ------------------------------ |
| 기관코드         | B552657             | B551182                        |
| 전체 병원 수     | 78,631              | 79,739                         |
| 초당 제한        | 30 TPS              | 30 TPS                         |
| **일 호출 한도** | **API 별 1,000/일** | **API 별 10,000/일**           |
| 데이터 갱신주기  | 일 1회              | 가이드에 언급 없음 — 확인 필요 |
| 총 콜수          | 78,693              | 877,237                        |

### 한도는 API 별이다. 그리고 우리가 세지 않는다.

한도는 **오퍼레이션 하나하나에 따로** 걸린다. HIRA 의 11종은 각자 10,000/일을 갖는다.
그래서 콜수가 NMC 의 11배인데도 **HIRA 가 훨씬 빨리 끝난다**. 병원 하나가 11개 API 를
1콜씩 쓰므로, 하루에 병원 10,000곳까지 완성할 수 있다.

반대로 NMC 는 개별 조회가 `basic` **하나뿐**이라 그 API 의 1,000/일이 그대로 병목이 된다.

콜수는 **우리가 세지 않는다**. 세면 반드시 어긋난다 — 실패한 콜이 한도에 잡히는지,
다른 프로세스가 같은 키를 쓰는지 알 수 없기 때문이다.
원본이 `resultCode 22`(요청제한횟수 초과)로 알려주면 그때 멈추고 다음 날 이어받는다.
`@krdata/core` 가 이것을 `KrDataQuotaError` 로 따로 던지고, 배치는 **실패가 아니라
"오늘은 여기까지"** 로 다룬다.

HIRA 는 한도에 걸린 **오퍼레이션만** 빼고 나머지로 계속 받는다. `equipment` 가 막혀도
`info` 는 아직 살아 있다. 그 병원은 미완성으로 남지만, 상세가 (병원, 오퍼레이션) 단위 행이라
다음 날 **못 받은 오퍼레이션만** 이어받는다.

`numOfRows` 는 두 기관 모두 상한이 없다. 10,000건 단위가 응답시간·메모리의 균형점이다.

## 병원 등급 분포

규모기관은 전체의 **5%** 뿐인데 데이터 밀도는 압도적이다. 여기부터 채운다.

| A 종합병원      | 380       | 01 상급종합        | 47        |
| B 병원          | 1,429     | 11 종합병원        | 338       |
| E 한방병원      | 613       | 21 병원            | 1,429     |
| M 치과병원      | 246       | 29 정신병원        | 261       |

|                 |           | 41 치과병원        | 247       |
|                 |           | 28 요양병원        | 1,285     |

8만 콜 써서 7.5만 개의 0을 받아올 이유가 없다.

# NMC 사다리

## N1 — 전체 병원 · 62콜 · 매일

| 데이터               | 방법                        | 콜  | 상태 |
| -------------------- | --------------------------- | --- | ---- |
| 병원 전체 78,631건   | `fulldown`, 10,000씩        | 8   | ✅   |
| 코드마스터 2,784건   | 페이징                      | 3   | ✅   |
| 달빛어린이병원 153건 | 필터 없이 1콜               | 1   | ❌   |
| 병원-진료과목 매핑   | **`QD` 역조회** (D001~D034) | ~50 | ❌   |

이 시점에 **이름·주소·좌표·지역·기관구분·진료시간(월~일+공휴일)·응급실 운영여부·진료과목**이 확보된다.
지역은 generated column + 인덱스로 이미 검색 가능하다. **"강남구 내과" 검색이 여기서 완성된다.**

## N2 — 규모기관 `basic` · 3,951콜 · **4일**

`basic` 한 API 에 1,000/일이라 하루 1,000곳이 상한이다. 30 TPS 로는 2분이면 끝날 양이지만
한도가 막는다. **NMC 의 병목은 처음부터 끝까지 `basic` 이다.**

`basic` 은 한 콜에 **68개 필드**를 준다 — 진료과목(`dgidIdName`), 병상수(`hpbdn`),
응급실 병상 세부(`o001~o038`), 중증질환 처치가능(`MKioskTy*`), 입원실·수술실·중환자실 운영 여부.

등급별로 실호출해 필드 채움률을 측정했다.

| 순위     | 등급             | 콜       | 응급실 운영   | 병상 | 응급실병상(o###) | 중증처치(MKiosk) | 진료과목 |
| -------- | ---------------- | -------- | ------------- | ---- | ---------------- | ---------------- | -------- |
| **N2-1** | 종합병원 (A)     | 380      | **376 (99%)** | 850  | 22               | **9~10**         | 25~26    |
| N2-2     | 병원 (B)         | 1,429    | 133 (9%)      | 185  | 6                | 0                | 9~20     |
| N2-3     | 한방병원 (E)     | 613      | 0             | 50   | 0                | 0                | 6~12     |
| N2-4     | 치과병원 (M)     | 246      | 0             | 5    | 0                | 0                | 10       |
| **N2-5** | **요양병원 (D)** | 1,283    | **0**         | 181  | 0                | 0                | 1~4      |
| _(대조)_ | _의원 (C)_       | _37,028_ | _1_           | _-_  | _0_              | _0_              | _1~2_    |

요양병원을 맨 뒤로 보낸다. 응급실 0곳·중증처치 0종이고, 얻는 병상수도 장기요양 병상이라
"지금 갈 병원 찾기" 라는 검색 목적과 거리가 멀다.

N2-2 이후가 실제로 더하는 것은 사실상 **병상수 하나**다. 진료과목은 N1 역조회로 이미 확보된다.

## N3 — 의원급 `basic` · 74,680콜 · **75일**

의원급은 병상 0, 장비 0~1종이다. 진료과목도 N1 역조회로 이미 있다.
**미뤄도 검색이 성립한다.** `basic` 이 하루 1,000곳이라 75일이 걸린다.

**NMC 는 여기서 끝난다.** 개별 API 가 `basic` 하나뿐이라 더 받을 것이 없다.

# HIRA 사다리

## H1 — 전체 병원 · 108콜 · 매일

| 데이터                  | 방법                           | 콜  | 상태 |
| ----------------------- | ------------------------------ | --- | ---- |
| 병원 전체 79,739건      | `hospital list`, 10,000씩      | 8   | ✅   |
| 코드 6종 214건          | 엔드포인트가 6개라 6콜         | 6   | ✅   |
| 병원-진료과목 434,638쌍 | **`dgsbjtCd` 역조회** (50과목) | ~94 | ❌   |

### 진료과목 역조회가 핵심이다

병원별로 `getSubjectInfo(ykiho)` 를 부르면 79,739콜이다.
병원 목록에 `dgsbjtCd` 필터가 있어 **과목별로 뒤집어 조회하면 ~94콜**이다. **850배** 차이다.

단건 API 가 추가로 주는 것은 **과목별 전문의수 하나뿐**이다. 그거 하나에 8만 콜을 쓸 이유가 없다.

역조회가 가능한 축은 **진료과목뿐**이다. `srchCd`(전문병원·특수진료)는 필터로 넣어도
조용히 무시된다(79,739건 그대로 나온다).

## 개별 조회 11종 — 한 병원을 끝내려면 11번 두드려야 한다

| 오퍼레이션   | 응답 | 내용                                                                  |
| ------------ | ---- | --------------------------------------------------------------------- |
| `info`       | 1행  | 요일별 진료시간·점심·접수·휴진·응급실 주야간 여부와 전화              |
| `facility`   | 1행  | 허가/표준/상급 병상, 정신과 개방·폐쇄, 중환자실, 격리, 수술실, 분만실 |
| `equipment`  | N행  | 보유 장비 코드와 대수                                                 |
| `special`    | N행  | 특수진료(시범사업 참여 — 방문진료·치매주치의 등)                      |
| `specialty`  | N행  | 전문병원 지정분야                                                     |
| `nursing`    | N행  | 병동 유형별 간호등급                                                  |
| `food`       | N행  | 식대가산 (영양사·조리사)                                              |
| `subject`    | N행  | 진료과목 + **과목별 전문의수**                                        |
| `specialist` | N행  | 세부 전문과목별 전문의수                                              |
| `etc-staff`  | N행  | 약사·영양사 등 인원수                                                 |
| `transport`  | N행  | 대중교통 안내                                                         |

**NMC 는 `basic` 한 콜이면 그 병원이 끝난다. HIRA 는 11콜을 써야 한 병원이 끝난다.**
그래서 HIRA 의 실행 단위는 **병원 등급**이고, 한 등급을 잡으면 **11종을 모두 돌려 그 등급을 완성**한다.
등급을 완성하지 않고 오퍼레이션별로 훑으면, 어느 병원도 완성되지 않은 채 콜만 소모된다.

## H2 ~ H8 — 규모기관 완성 · 46,541콜 · 등급 단위

한 등급 = 병원 수 × 11종. 그 등급이 **완전히 끝난 뒤** 다음 등급으로 넘어간다.

| 단계     | 등급              | 병원 수 | 콜 (×11)   | API 별 콜 | 소요    |
| -------- | ----------------- | ------- | ---------- | --------- | ------- |
| **H2**   | 상급종합 (01)     | 47      | 517        | 47        | 1분     |
| **H3**   | 종합병원 (11)     | 338     | 3,718      | 338       | 8분     |
| **H4**   | 병원 (21)         | 1,429   | 15,719     | 1,429     | 35분    |
| **H5**   | 정신병원 (29)     | 261     | 2,871      | 261       | 7분     |
| **H6**   | 한방병원 (92)     | 624     | 6,864      | 624       | 16분    |
| **H7**   | 치과병원 (41)     | 247     | 2,717      | 247       | 6분     |
| **H8**   | **요양병원 (28)** | 1,285   | 14,135     | 1,285     | 32분    |
| **소계** |                   | 4,231   | **46,541** | **4,231** | 1.8시간 |

**API 별 콜이 4,231 뿐이다. 한도(10,000/일) 아래라 하루에 규모기관 전체가 끝난다.**
콜수 46,541 만 보면 커 보이지만, 11개 API 에 나뉘어 있어 어느 API 도 한도의 절반을 못 넘는다.

**H2(상급종합 47곳)는 517콜·1분이면 끝난다.**
그 47곳은 병상·장비·특수진료·전문병원·간호등급·전문의수가 **전부 채워진 완성 상태**가 된다.

소요 시간은 실측 기준이다(병원 10곳 × 11종 = 110콜에 15초 → 약 7.3콜/초).

전문병원(`specialty`)은 병원급 이상만 지정되므로 H2~H8 로 **전수 파악이 끝난다**.

### 등급 안에서 뺄 수 있는 오퍼레이션

- `subject` — 병원-과목 매핑은 H1 역조회로 이미 있다. **과목별 전문의수 하나만** 추가된다
- `specialist` `etc-staff` `transport` — 가치가 낮다. 급하면 뺀다

11종 → 7종으로 줄이면 규모기관이 46,541콜 → **29,617콜**이 된다.

| 단계     | 등급          | 병원 수 | 콜 (×11)    | API 별 콜  | 소요    |
| -------- | ------------- | ------- | ----------- | ---------- | ------- |
| **H9**   | 의원 (31)     | 37,789  | 415,679     | 37,789     | 4일     |
| **H10**  | 치과의원 (51) | 19,380  | 213,180     | 19,380     | 2일     |
| **H11**  | 한의원 (93)   | 14,873  | 163,603     | 14,873     | 1.5일   |
| **H12**  | 보건기관 등   | 3,466   | 38,126      | 3,466      | 1일     |
| **소계** |               | 75,508  | **830,588** | **75,508** | **8일** |

API 별로 하루 10,000곳이 상한이므로 75,508곳이면 8일이다. 콜수 83만이 무섭게 보이지만
11개 API 에 나뉘므로 실제 제약은 **병원 수 ÷ 10,000** 이다.

의원급은 병상 0, 장비 0~1종이다. 진료과목도 H1 역조회로 이미 있다. **미뤄도 검색이 성립한다.**
급하면 `equipment`(장비)와 `special`(시범사업 참여)만 받아도 된다 — 그래도 8일은 같다
(병원 수가 제약이지 콜수가 제약이 아니다).

**콜수는 HIRA 가 11배지만, 끝나는 것은 HIRA 가 9배 빠르다.**

한도가 API 별이기 때문이다. HIRA 는 11개 API 가 각자 10,000/일을 가지므로 하루에 병원
10,000곳을 완성할 수 있다. NMC 는 개별 조회가 `basic` 하나뿐이라 그 API 의 1,000/일이
그대로 상한이 된다 — 하루 1,000곳이다.

**NMC `basic` 이 전체 계획의 병목이다.** 79일 중 75일이 의원급 `basic` 이다.
그런데 의원급 `basic` 은 얻는 게 거의 없다(병상 0, 장비 0~1종, 진료과목은 역조회로 이미 확보).
**N3 를 빼면 NMC 는 4일, HIRA 는 1일이면 규모기관까지 다 끝난다.**

## 권장 순서

````
1일차   N1 + H1 (벌크·역조회)  →  "강남구 내과" 검색 완성
1일차   H2~H8 (규모기관 4,231곳 × 11종)  →  HIRA 규모기관 100% 완성
2~5일차 N2 (규모기관 basic, 하루 1,000곳)  →  NMC 규모기관 완성
이후    H9~H12 (의원급, 8일)  →  필요하면
보류    N3 (의원급 basic, 75일)  →  얻는 게 적다

# 공통 규칙

## 이어받기가 필수다

단건형은 한 번에 못 끝낸다(NMC `basic` 은 79일이 걸린다). **못 받은 것이 곧 작업 큐**다.
커서를 따로 관리하지 않는다.

```sql
-- NMC: basic 을 아직 안 받은 병원
SELECT hpid FROM nmc_hospital WHERE basic_synced_at IS NULL

-- HIRA: (병원, 오퍼레이션) 쌍이 행이다. 행이 없으면 아직 안 받은 것이다.
SELECT h.ykiho FROM hira_hospital h
 WHERE (SELECT COUNT(*) FROM hira_hospital_detail d WHERE d.ykiho = h.ykiho) < 11
````

배치는 매일 같은 크론으로 1단계부터 끝까지 훑는다. 한도에 걸리면 원본이 알려주고,
다음 날 못 받은 것부터 이어간다. `--limit` 은 사고 방지용 안전판일 뿐 한도 관리 수단이 아니다.

## 저장 위치

- **검색 축이 되는 것**(진료과목·장비·전문병원) → **정규화 테이블**. 다대다이고 조인·인덱스가 필요하다.
- **화면 표시용 상세**(진료시간·주차·병상) → **JSON 컬럼**. 오퍼레이션별로 따로 둔다.
- 원본 미러(`data`)에는 다른 API 의 결과를 섞지 않는다. 매일 도는 sync 가 통째로 덮어쓰기 때문이다.
  (지역처럼 SDK 가 응답 시점에 계산해 넣는 파생 필드는 예외다. 항상 같은 값이 나오므로 안전하다)

```
nmc_hospital          data(fulldown) · basic(JSON) · basic_synced_at
nmc_hospital_subject  (hpid, subject_cd, subject_nm, source, synced_at)
                       source = 'list'(N1 역조회) → 'basic'(N2·N3 의 dgidIdName 으로 덮어씀)

hira_hospital           data(list) · detail(JSON) · facility(JSON) · *_synced_at
hira_hospital_subject   (ykiho, dgsbjt_cd, dgsbjt_nm, sdr_cnt, source, synced_at)
                         source = 'list'(H1 역조회) → 'subject'(H3 에서 전문의수까지 채우며 덮어씀)
hira_hospital_equipment (ykiho, oft_cd, oft_nm, oft_cnt)
hira_hospital_srch      (ykiho, tp, srch_cd, srch_nm)   전문병원 · 특수진료
```

`dgidIdName`(쉼표 구분 과목명)은 NMC 코드마스터 `D000` 과 **25/25 매칭**된다. 코드로 무손실 환산된다.

# 남은 확인 사항

- **HIRA 갱신주기.** 가이드에 없다. 확인 전까지는 전량 재적재를 가정한다.
- **운영계정 전환 시 한도.** 현재 한도(NMC API 별 1,000/일, HIRA API 별 10,000/일) 기준으로
  계산했다. 운영계정으로 올리면 NMC 의 79일이 그만큼 줄어든다.
