# 공공데이터포털 운영계정 신청 문안

개발계정 일 한도로는 전량 적재가 끝나지 않는다. **API 마다 활용사례를 등록하고 운영계정으로 전환**해야 한다.
이 문서는 신청 화면에 **그대로 복사해 넣을 문안**이다.
`서비스 설명` 은 서비스가 하나라 **공통 한 벌**이고, `활용사례명` 과 `기능 및 서비스 화면` 만 API 별로 있다.

- 건수·콜수의 근거는 [`krdata-cache-plan.md`](krdata-cache-plan.md) 다. 숫자를 고칠 때는 그쪽부터 본다.
- API 특이사항은 [`../clients/README.md`](../clients/README.md) 에 있다.
- 신청 단위는 **오퍼레이션이 아니라 서비스**다. 한 서비스에 오퍼레이션이 여러 개 묶여 있어도 신청은 한 번이다.

작성 기준 2026-08. 서비스 기준은 **MediFinder(medifinder.kr)** 다 — 실제 운영 중인 병원 검색 서비스라
심사에서 확인이 가능하다. 사업자등록 조회(국세청)만 예외로 Hans API(plzhans.com) 기준으로 쓴다.

## 문안에 쓰지 않는 것

**서비스 설명은 서비스가 무엇인지 쓰는 칸이다.** 심사자가 알고 싶은 것은 이 데이터로 이용자에게
무엇을 보여 주느냐이지, 우리가 그것을 어떻게 굴리느냐가 아니다. 아래는 문안에 넣지 않는다.

- **하루 몇 번 부르는지, 전량이 몇 콜인지.** 신청 사유를 묻는 칸이 따로 있을 때만 쓴다(아래).
- **내려받아 보관한다는 서술.** 저장 방식은 묻지도 않은 것을 스스로 꺼내는 꼴이라,
  이용약관·보관 범위를 되묻는 자리를 만든다. 갱신 주기·배치·미리 받아 두는 동작도 같다.
- **내부 구조.** 어느 테이블에 넣는지, 어느 화면이 어느 오퍼레이션을 부르는지.

숫자와 근거는 [`krdata-cache-plan.md`](krdata-cache-plan.md) 와 이 문서의 **문안 바깥**에 남긴다 —
지우는 게 아니라 자리를 옮기는 것이다.

### 신청 사유를 따로 묻는 칸이 있으면

트래픽 증량 사유를 별도로 받는 서식이 있다. 그때만 아래를 쓴다. 여기서도 콜수는 적지 않는다.

```text
전국 병·의원 전체를 대상으로 하는 서비스라 특정 지역이나 일부 기관만으로는 검색이 성립하지 않습니다.
개발계정 한도로는 전체 기관의 정보를 최신으로 유지하기 어려워, 정식 서비스 운영을 위해 증량을 신청합니다.
```

신청서 상단에 반복해서 넣는 값이다.

| 항목        | 값                                         |
| ----------- | ------------------------------------------ |
| 활용목적    | 웹 사이트 개발                             |
| 서비스명    | MediFinder                                 |
| 서비스 URL  | https://medifinder.kr                      |
| 시스템 유형 | 반응형 웹 (PC · 모바일 브라우저 공용)      |
| 이용료      | 무료. 로그인·결제 없이 누구나 이용         |
| 지원 언어   | 한국어 · 영어 · 일본어 · 중국어            |
| 출처 표기   | 화면 하단에 제공기관과 공공데이터포털 표기 |
| 운영 주체   | 신청 계정의 사업자 정보와 동일하게 기재    |

## 서비스 설명 (공통)

**서비스는 하나이므로 설명도 하나다.** 아래 문안을 1~8번 신청에 **그대로** 붙여넣는다 —
API 마다 달라지는 것은 `기능 및 서비스 화면` 이지 서비스가 무엇이냐가 아니다.
**9번(국세청)만 다른 서비스**라 그 절에 따로 적어 두었다.

```text
MediFinder(https://medifinder.kr)는 전국 병·의원을 지역과 진료과목, 진료시간으로 찾아주는 무료 웹 서비스입니다.
로그인이나 결제 없이 누구나 이용할 수 있으며, 한국어·영어·일본어·중국어를 지원해 국내 이용자는 물론 국내에 체류하거나 방문하는 외국인도 진료받을 수 있는 병원을 찾을 수 있도록 만들었습니다.

병원을 고를 때 필요한 정보는 공공기관이 이미 공개하고 있지만 여러 곳에 흩어져 있습니다.
어느 병원이 무슨 과를 보는지, 지금 문을 열었는지, 그 분야 전문병원으로 지정받았는지, 진료 적정성 평가에서 어떤 등급을 받았는지, 비급여 진료비는 얼마인지가 서로 다른 자리에 있습니다.
MediFinder는 이 정보를 한 화면에서 볼 수 있게 모아, 이용자가 광고나 후기가 아니라 공개된 자료를 근거로 병원을 고를 수 있도록 합니다.

이용자는 시도와 시군구를 고르고 진료과목·병원 등급·보유 장비·전문분야 같은 조건으로 병원을 찾습니다.
결과는 목록으로 훑거나 지도 위에서 위치를 확인할 수 있고, 현재 위치를 허용하면 가까운 순으로 정렬해 보여 줍니다.
병원을 고르면 연락처와 요일별 진료시간, 진료과목과 의료진, 병상과 보유 장비, 평가 등급, 찾아가는 길과 비급여 진료비를 정리한 상세 화면으로 이어집니다.

밤이나 휴일에 갑자기 아플 때를 위해 응급실과 달빛어린이병원을 홈 화면 전면에 두었고, 자연어로 물으면 검색 조건으로 바꿔 주는 AI 검색도 제공합니다.
증상이나 상황을 문장으로 적으면 지역과 진료과목 조건을 잡아 병원을 찾아 주며, 응급 상황으로 판단되면 병원을 안내하기에 앞서 119 연락과 가까운 응급실 방문을 먼저 알립니다.

각 화면에는 자료 출처로 해당 제공기관과 공공데이터포털을 표기하며, 원본 데이터를 파일 형태로 재배포하거나 판매하지 않습니다.
```

> 심사에서 이 신청이 어느 데이터를 쓰는지 되물으면, 그 API 의 `기능 및 서비스 화면` 첫 줄을
> 설명 끝에 한 문장으로 붙인다. 평소에는 붙이지 않는다 — 여덟 벌을 서로 다르게 관리하게 된다.

## 1. 건강보험심사평가원_병원정보서비스

### 활용사례명

```text
MediFinder(medifinder.kr) 병원 찾기 서비스 - 병원 기본정보
```

### 기능 및 서비스 화면

```text
[검색 화면] https://medifinder.kr/search
- 시도·시군구를 고르고 병원 이름으로 검색합니다. 본 API의 시도·시군구·주소·요양기관명 필드를 사용합니다.
- 상세 검색에서 병원 등급(상급종합·종합병원·병원·의원·치과·한방 등)과 진료과목을 조건으로 걸 수 있습니다. 종별코드와 진료과목 역조회 결과를 사용합니다.
- 목록에는 병원 이름, 종별, 주소, 전화번호를 표시하고, 결과 건수와 페이지를 함께 보여줍니다.
- '내 위치로 찾기'를 선택하면 본 API의 좌표(XPos·YPos)로 거리를 계산해 가까운 순으로 정렬합니다.
- 목록/지도 전환 버튼으로 같은 결과를 지도 위 마커로도 볼 수 있습니다. 마커 좌표 역시 본 API 값입니다.

[병원 상세 화면] https://medifinder.kr/hospital/{병원}
- 상단에 병원 이름과 종별을 표시하고, 전화 걸기·길찾기·공유 버튼을 제공합니다. 전화번호와 좌표를 사용합니다.
- '소개' 탭에 대표번호, 홈페이지, 진료과목을 표시합니다.
- '위치' 탭에 주소와 지도, 주소 복사 기능을 제공하고, 같은 좌표를 기준으로 '근처의 비슷한 병원'을 함께 보여줍니다.

[홈 화면] https://medifinder.kr
- 상급종합병원 등 종별 기준 추천 목록을 카드로 보여줍니다. 종별코드로 추린 결과입니다.

[AI 검색] 홈 화면의 'AI에게 문의하기'
- "무릎이 아픈데 어디로 가야 해" 같은 자연어 질문을 지역·진료과목·종별 조건으로 바꿔 위 검색 결과를 보여줍니다. 조건에 대응하는 값은 모두 본 API에서 온 것입니다.
```

## 2. 건강보험심사평가원_병원코드정보서비스

### 활용사례명

```text
MediFinder(medifinder.kr) 병원 찾기 서비스 - 검색 조건 코드
```

### 기능 및 서비스 화면

```text
[검색 화면] https://medifinder.kr/search
- 시도 선택 상자와 시군구 선택 상자를 주소코드(getAddrCodeList)로 채웁니다. 시도를 고르면 그에 속한 시군구만 남습니다.
- '등급' 필터의 상급종합·종합병원·병원·요양병원·치과의원·한의원 항목을 종별코드(getMedicInsttClassesCodeList)로 채웁니다.
- '진료과목' 필터의 내과·소아청소년과·정형외과 등 선택 목록을 진료과목코드(getMdlrtSbjectCodeList)로 채우고, 의과·치과·한방 세 갈래로 묶어 보여줍니다.
- '보유장비' 필터의 CT·MRI 등 선택 목록을 의료장비코드(getMedicEquipmentCodeList)로 채웁니다.
- '전문분야' 필터를 전문병원 지정분야코드(getSpcHospCodeList)로, '특수진료' 필터를 특수진료코드(getSpclMdlrtCodeList)로 채웁니다.

[병원 상세 화면] https://medifinder.kr/hospital/{병원}
- '소개' 탭의 진료과목, '규모' 탭의 보유 장비, 전문분야와 특수진료 배지를 모두 코드가 아닌 이름으로 표시합니다. 이 변환에 본 서비스의 코드표를 사용합니다.

[다국어 표기]
- 영어·일본어·중국어 화면에서도 같은 코드를 기준으로 항목을 대응시켜 보여줍니다.
```

## 3. 건강보험심사평가원_의료기관별상세정보서비스 2.8

**가장 급한 신청이다.** 전량이 877,237콜이고, 개별 조회는 이 서비스 말고 대체 수단이 없다.

### 활용사례명

```text
MediFinder(medifinder.kr) 병원 찾기 서비스 - 병원 상세정보
```

### 기능 및 서비스 화면


## 9. 국세청_사업자등록정보 진위확인 및 상태조회

**기준 서비스가 다르다.** MediFinder 가 아니라 Hans API(plzhans.com) 에서 쓰는 API 다.
실시간 호출이라 이용자 수에 비례해 콜이 늘어난다 — 배치로 줄일 수 없는 유일한 API 다.

### 활용사례명

```text
Hans API(plzhans.com) 사업자등록 조회 - 사업자번호 확인
```

### 서비스 설명 — 이 건만 다르다

**공통 문안을 쓰지 않는다.** MediFinder 가 아니라 Hans API 기준이다.

```text
Hans API(https://plzhans.com)는 여러 공공·민간 원천의 데이터를 일관된 규격으로 정리해 제공하는 API 서비스입니다.
개발자가 앱을 등록하고 키를 받아 호출하는 방식이며, 이용 안내와 명세는 https://docs.plzhans.com 에서 공개하고 있습니다.

본 서비스는 Hans API의 사업자등록 조회 기능입니다.
사업자등록번호로 납세자상태(계속사업자·휴업자·폐업자)와 과세유형을 확인하는 상태조회, 그리고 사업자등록번호·개업일자·대표자성명이 국세청 등록정보와 모두 일치하는지 확인하는 진위확인 두 가지를 제공합니다.

거래처나 회원의 사업자등록번호를 입력받는 서비스에서는 그 번호가 실재하는지, 이미 폐업한 곳은 아닌지 확인할 수단이 필요합니다.
Hans API는 국세청 응답을 그대로 노출하지 않고 코드 값을 사람이 읽을 수 있는 표기로 바꾸어 전달하며, 오류 응답도 표준 형식으로 정리해 돌려줍니다.
등록되지 않은 번호는 오류가 아니라 '미등록' 결과로 돌려주어, 이용하는 쪽이 예외 처리를 단순하게 할 수 있도록 했습니다.

개인정보 보호를 위해 대표자성명과 개업일자는 URL이 아닌 요청 본문으로 받아 접근 로그에 남지 않게 하고 있습니다.
조회 결과는 이용자에게 응답으로 전달할 뿐 따로 축적하거나 재배포하지 않습니다.

응답 화면과 문서에는 자료 출처로 국세청과 공공데이터포털을 표기합니다.
```

### 기능 및 서비스 화면

```text
[API 엔드포인트] https://docs.plzhans.com 의 '사업자등록 조회'
- 상태조회 (GET /nts/business/{사업자번호}/status)
  사업자등록번호를 받아 등록 여부, 납세자상태(계속·휴업·폐업), 과세유형, 폐업일자를 돌려줍니다.
- 진위확인 (POST /nts/business/{사업자번호}/verify)
  사업자등록번호·개업일자·대표자성명을 받아 국세청 등록정보와 일치하는지 확인하고, 함께 상태 정보도 돌려줍니다.

[문서 화면] https://docs.plzhans.com
- 요청·응답 예시와 사업자번호 표기 규칙(하이픈 포함 여부는 서버가 자동 처리), 미등록 번호의 응답 형태를 안내합니다.
- 국세청 시스템 점검 중에는 조회가 일시적으로 실패할 수 있다는 안내를 표시합니다.
```
