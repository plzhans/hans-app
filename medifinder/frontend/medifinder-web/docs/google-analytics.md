# 이용 통계 (Google Analytics)

방문 통계를 무엇으로 어떻게 재는지, 그리고 **왜 GA 콘솔 설정을 코드와 같은 급으로 다루는지**.

이 문서가 따로 있는 이유는 하나다 —
**GA 는 설정의 절반이 저장소 밖(콘솔)에 있고, 그 절반이 개인정보처리방침의 근거다.**
코드만 보면 무엇을 약속했는지 알 수 없고, 콘솔만 보면 왜 그 값인지 알 수 없다.

## 환경 분기

| 환경 | `VITE_GOOGLE_ANALYTICS_ID` | 결과 |
| --- | --- | --- |
| local | 빈 값 | 스크립트를 받지 않는다 |
| develop | 빈 값 | 받지 않는다 |
| production | `G-` 로 시작하는 측정 ID | 켜진다 |

**그래서 `index.html` 에 스니펫을 넣으면 안 된다.**
Vite 가 `%VITE_...%` 치환은 해 주지만, 값이 비어도 `gtag.js` 는 그대로 로드되고 요청이 나간다 —
"비우면 끈다" 가 성립하지 않는다.
스크립트 태그를 코드에서 만들고 **ID 가 없으면 아예 붙이지 않는** 쪽이라야 분기가 선다.

[monitoring/instrument.ts](../src/shared/monitoring/instrument.ts) 의 Sentry 가 DSN 없으면
`init` 을 아예 하지 않는 것과 같은 모양이고, 같은 이유다.

## 페이지뷰는 직접 쏜다

React Router 는 화면을 바꿔도 페이지를 새로 열지 않는다. 방법이 둘 있다.

구글은 History API 를 쓰는 SPA 에 **향상된 측정**을 권장한다
([Measure single-page applications](https://developers.google.com/analytics/devguides/collection/ga4/single-page-applications)).
`createBrowserRouter` 가 그 경우이니 맡겨도 된다.

**그런데 이 앱은 수동으로 간다.** `/ko/*` 로 들어오면 `StripKoPrefix` 가 접두사를 뗀 정식 URL 로
한 번 더 갈아치우는데(`replaceState`), 향상된 측정은 **그 중간 URL 까지 센다** — 한 번의 방문이
`/ko/search` 와 `/search` 두 줄이 된다. 언제 보낼지를 우리가 쥐고 있어야 그걸 건너뛸 수 있다.
포털웹(hansapp-web)도 같은 방식이라 저장소 안에서 방식이 갈리지 않는다는 점도 있다.

구현은 두 조각이다.

- [analytics/gtag.ts](../src/shared/analytics/gtag.ts) — `initGa()` 가 `send_page_view: false` 로 설정하고,
  `trackPageView()` 가 `page_view` 이벤트를 `page_location`(전체 URL)과 함께 보낸다
- [App.tsx](../src/app/App.tsx) 의 `RouteTracker` — 라우터 안에서 `useLocation` 을 보고 호출한다.
  기본 언어 접두사 경로는 건너뛴다

**콘솔 토글을 반드시 함께 꺼야 한다.** `send_page_view: false` 는 `config` 시점의 한 번만 막고
향상된 측정의 기록 이벤트는 그대로 살아 있다 — 둘 다 살아 있으면 전환마다 두 번 집계된다.
아래 설정 표의 "브라우저 기록 이벤트 기반 페이지 변경" 이 그 짝이다.

## 콘솔 설정

두 종류를 갈라 둔다. **방침이 사실이라고 주장하는 값**과, 그냥 **우리가 정한 값**이다.

### 방침과 묶인 값 — 바꾸면 방침이 거짓이 된다

| 설정 자리 | 값 | 바꾸면 |
| --- | --- | --- |
| 데이터 수집 > 구글 신호 데이터 | **사용 안 함** | 분석 도구의 광고 기능을 쓰지 않는다는 고지가 거짓이 된다 |
| 데이터 수집 > 광고 개인 최적화 | **사용 안 함** | 위와 같다 |

이 둘은 콘솔에서 켜는 순간 방침을 함께 고쳐야 한다.
**애드센스를 붙일 때 어차피 이 조항이 통째로 바뀐다** — 그때 같이 본다.

### 운영 판단으로 정한 값 — 바꿔도 방침은 안 깨진다

| 설정 자리 | 값 | 이유 |
| --- | --- | --- |
| 데이터 설정 > 데이터 보관 > **이벤트 데이터** | **14 개월** (2 / 14 개월, 기본값 2 개월) | 전년 동월 비교가 가능한 최대치 |
| 데이터 설정 > 데이터 보관 > **사용자 데이터** | **14 개월** (2 / 14 개월, 기본값 2 개월) | 위와 같다 |
| 데이터 설정 > 데이터 보관 > **새로운 활동 시 사용자 데이터 재설정** | **켬** | 재방문자를 신규로 다시 세지 않는다 |
| 데이터 스트림 > 향상된 측정 > 페이지 조회수 > 고급 설정 > **브라우저 기록 이벤트 기반 페이지 변경** | **끔** | 코드가 직접 쏘므로, 켜 두면 전환마다 두 번 집계된다 |

**보관 기간은 두 칸이 따로 있다.** 이벤트 데이터와 사용자 데이터를 각각 고르며 둘 다 기본값이 2 개월이라,
한쪽만 바꾸고 끝내기 쉬운 자리다.

**"새로운 활동 시 사용자 데이터 재설정" 은 사용자 데이터에만 걸린다.**
켜 두면 그 이용자가 다시 올 때마다 식별자의 만료 시계가 처음부터 다시 간다 —
매달 오는 사람의 식별자는 사실상 계속 남는다는 뜻이다.
**방침이 개월 수를 적지 않기 때문에 이 값은 자유다.** 개월 수를 적기로 바꾸면 이 토글부터 다시 봐야 한다.

보관 기간이 걸리는 대상은 **탐색 분석과 유입경로 보고서에 쓰이는 개별 기록이다.**
표준 보고서의 집계 수치(화면별 방문 수 등)는 그 기간이 지나도 남는다 —
방침이 "집계된 통계는 그 이후에도 남는다" 고 적은 것이 이 구분이다.

## 개인정보처리방침과의 연결

GA 를 켜면 방침이 아래를 사실로 주장한다.
**어느 조에 있는지는 여기 적지 않는다** — 방침이 개정되면 조 번호가 밀리고, 그때 이 문서가 조용히 틀린다.
조문은 [privacy.ko.json](../src/features/legal/content/privacy.ko.json) 에서 직접 본다.

- 수집 항목에 이용 통계가 있고, 목적은 서비스 개선이다
- 보유 기간은 **"분석 도구의 보관 정책에 따라"** 다 — 개월 수를 적지 않는다
- Google LLC 가 수탁자이자 국외 이전 대상이다
- 쿠키가 저장되지만 광고·추적 쿠키는 없다
- 분석 도구의 광고 기능을 쓰지 않는다

**방침은 도구 이름과 쿠키 이름을 적지 않는다.**
국내 대형 서비스(당근 · 카카오 · 원티드 등)의 방침을 훑어 보고 맞춘 수준이다 —
그쪽은 GA 를 "외부 분석 툴" 로 뭉뚱그리고, 쿠키 이름도 보유 개월 수도 적지 않는다.
`Google LLC` 만 위탁 · 국외이전 표에 이름으로 남는데, 그건 법이 수탁자를 구체적으로 밝히라고 요구해서다.

이 선택의 대가는 분명하다 — **검증 가능한 약속 하나가 검증 불가능한 문장이 됐다.**
대신 콘솔에서 보관 값을 바꿔도 방침을 다시 고칠 일이 없다.

**한국어본이 정본이고 영어본은 번역이다.** 한쪽을 고치면 다른 쪽도 같이 고친다 —
규칙은 [content/index.ts](../src/features/legal/content/index.ts) 머리 주석에 있다.

## 확인 방법

운영에만 켜지므로 로컬에서는 확인할 수 없다.

- **실시간 보고서** — 배포 후 자기 브라우저로 몇 화면 이동해 보면 즉시 뜬다
- **DebugView** — 크롬 확장 "Google Analytics Debugger" 를 켜고 접속하면
  이벤트 단위로 보인다. 화면을 옮길 때 `page_view` 가 **한 번만** 나가는지 여기서 본다
- **쿠키** — 개발자 도구 > 애플리케이션 > 쿠키에 `_ga` 와 `_ga_<측정 ID>` 둘만 있어야 한다.
  셋째가 보이면 우리가 심은 적 없는 것이므로 무엇인지부터 확인한다

## 알려진 제약

- **Capacitor 앱은 아직 고려하지 않았다.**
  네이티브를 붙이면 같은 번들이 웹뷰에서 돌면서 `page_location` 이 `capacitor://localhost/...` 로 찍혀
  웹 리포트에 섞인다. [native.ts](../src/shared/lib/native.ts) 로 갈라 데이터 스트림을 나누거나
  `platform` 파라미터를 붙이는 판단이 그때 필요하다.
- **이벤트 설계는 없다.** 지금은 page_view 만 본다.
  검색·상세 열람 같은 행동을 이벤트로 남기려면 무엇을 왜 재는지부터 정하고,
  **정하는 순간 방침의 수집 항목이 다시 늘어난다.**
